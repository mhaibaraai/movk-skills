# 审查维度与检查清单

五组共 36 个检查项。每项都要落到一个判定结论，**漏掉某项与该项合格是两回事**，不能混为一谈。

## 判定三态

每个检查项只能给出三种结论之一：

| 结论 | 含义 | 写进报告的方式 |
| --- | --- | --- |
| 合格 | 有证据表明该项无问题 | 计入统计，不单独列条 |
| 存在问题 | 有证据表明该项有问题 | 按分级列进对应小节，必须带位置、原文、依据 |
| 无法判定 | 没有足以判定的证据 | **必须在概览里列出编号与原因**，不得静默略过 |

判成「无法判定」的典型原因：材料未提供（依据材料缺失、`pending_ocr` 未识别）、来源格式取不到（PDF 没有段落缩进）、模板未收录该条款。

**没有证据就写「无法判定」，不要写「可能存在」「建议关注是否……」**——后者看似谨慎，实际把模型的猜测伪装成了审查结论。

## 分级标准

| 级别 | 判定规则（命中任一即可） |
| --- | --- |
| 必须修改 | 影响合同效力；金额、数量、税率错误或自相矛盾；责任主体或责任归属不清；与签约依据冲突；缺少违约责任、争议解决这类必备条款 |
| 建议修改 | 表述不严谨、有歧义；条款对己方不利但不致命；与标准模板存在实质改写；期限表述不可计算 |
| 提示关注 | 错别字、标点、编号不连续；排版格式与模板不一致；疑似 OCR 误识需人工核对 |

排版类问题一律「提示关注」——它不影响合同效力，但影响定稿质量。

## 取证规则

- 每条问题必须同时给出**位置**（条款号或小节标题）、**原文片段**（30 字以内，用「」括起）、**依据来源**（哪份文件的哪个位置，或 `styles.py` 的哪个字段）。三者缺一不算完成审查。
- 金额、日期、单位名称一律**逐字引自材料原文**。换算结果（如分项之和）要写明「由 X + Y 算得」，不能当成原文引用。
- 条款缺失的唯一依据是标准模板正文，模板里没写的条款不算缺失。
- 风险提示只依据通用合同法律常识，**不引用法条编号、不引用企业内部制度条款**——没有检索能力就不要装作有。
- 同一问题只在最贴切的一节写一次，其余小节引用其编号。

## A 组：基础文本（12 项）

**金额**（A1–A5，实测最容易出问题的地方）

| 编号 | 检查项 | 判定方法 |
| --- | --- | --- |
| A1 | 大写与小写金额一致 | 逐处比对，含币种与「元 / 万元」口径 |
| A2 | 分项之和等于合同总价 | 表格分项相加后与总价比对 |
| A3 | 单价 × 数量等于分项金额 | 逐行验算 |
| A4 | 含税 / 不含税口径自洽 | 不含税 × (1 + 税率) 是否等于含税价 |
| A5 | 合同价与签约依据金额一致 | 与中标通知书、询比价结果审批表、会议纪要交叉核对 |

A1–A5 要做成一张交叉核对矩阵，逐格给结论：

| | 合同大写 | 合同小写 | 分项之和 | 单价×数量 | 依据中标价 |
| --- | --- | --- | --- | --- | --- |
| 值 | | | | | |
| 与合同小写是否一致 | — | — | | | |

矩阵里任一格取不到值（如依据材料未提供），该格写「无法判定」并说明缺哪份材料。

**日期与期限**（A6–A7）

| 编号 | 检查项 | 判定方法 |
| --- | --- | --- |
| A6 | 签订、生效、履行、质保各日期齐全且不矛盾 | 逐个列出后检查先后关系 |
| A7 | 期限表述可计算 | 「30 日内」是否写明起算点、是否区分日历日与工作日 |

**主体与完整性**（A8–A10）

| 编号 | 检查项 | 判定方法 |
| --- | --- | --- |
| A8 | 甲乙双方名称在正文、落款、公章处一致 | 逐处比对全称，简称与全称混用也算问题 |
| A9 | 无残留未填写的空白项 | 搜 `____`、`XXX`、连续空格、模板占位符 |
| A10 | 附件在正文中被引用且实际随附 | 正文附件清单与压缩包内文件互查 |

**文字**（A11–A12）

| 编号 | 检查项 | 判定方法 |
| --- | --- | --- |
| A11 | 无错别字、漏字、重复字 | 通读正文 |
| A12 | 标点规范 | 全角半角混用、括号不成对、分号句号混乱 |

## B 组：排版格式（5 项）

依据 `styles.py` 的输出判定，**不靠正文文本猜**。

| 编号 | 检查项 | 证据字段 |
| --- | --- | --- |
| B1 | 正文字体与模板一致 | `diffs` 的「正文字体」 |
| B2 | 正文字号与模板一致 | `diffs` 的「正文字号」 |
| B3 | 行距与模板一致 | `diffs` 的「行距（磅）」，注意口径 `note` |
| B4 | 首行缩进、页面尺寸、页边距与模板一致 | `diffs` 的对应项 |
| B5 | 顶层条款序号连续，交叉引用指向存在的条款 | `articles.gaps` + 正文里的「见第 X 条」 |

合同正文是 PDF 时，首行缩进、对齐、右边距与下边距天然取不到，相关项判「无法判定」并写明原因。`headings` 是按字号推断的，措辞用「疑似标题」，不要断言层级错误。

## C 组：风险合规（12 项）

逐项核对「有没有」与「对谁有利」。条款缺失记进 D 组，条款存在但对己方不利记本组。

| 编号 | 条款 | 重点 |
| --- | --- | --- |
| C1 | 付款 | 预付款比例、进度款节点、尾款与质保金比例、付款前提（验收合格、发票到达） |
| C2 | 违约责任 | 双方是否对等、违约金比例与上限、逾期交付与逾期付款的计算方式 |
| C3 | 质量与验收 | 验收标准、验收期限、不合格的处理、质保期与质保责任 |
| C4 | 知识产权 | 成果归属、许可范围、第三方侵权的责任承担（技术服务类必查） |
| C5 | 保密 | 范围、期限、违约后果 |
| C6 | 安全环保 | 责任划分、事故责任、资质要求（施工与运维类必查） |
| C7 | 廉洁 | 廉洁从业条款是否具备（国企合同的常规必备项） |
| C8 | 分包与转包 | 是否允许、是否需书面同意、禁止转包的表述 |
| C9 | 不可抗力 | 定义、通知义务、后果处理 |
| C10 | 合同解除 | 解除情形、通知程序、解除后的结算方式 |
| C11 | 争议解决 | 诉讼或仲裁二选一且唯一，管辖地明确且对己方不构成不便 |
| C12 | 履约担保 | 是否约定保证金或保函及退还条件 |

## D 组：模板差异（3 项）

`references/templates/<类型>.docx` 抽出的正文是唯一依据。

| 编号 | 检查项 | 输出要求 |
| --- | --- | --- |
| D1 | 模板有而合同无（条款缺失） | 列出条款名称与模板要求原文 |
| D2 | 合同有而模板无（新增条款） | 说明新增内容与是否合理 |
| D3 | 两者都有但实质改写 | 写明改动点与对己方的影响 |

模板未取到时，D1–D3 全部判「无法判定」，并在概览与材料完整性说明里同时写明。

## E 组：与签约依据的一致性（4 项）

本组最能发现实质问题。不一致一律「必须修改」，并写明两边原文与出处文件名。

| 编号 | 检查项 | 比对对象 |
| --- | --- | --- |
| E1 | 合同价 vs 中标价 | 询比价结果审批表、中标通知书 |
| E2 | 合同范围 vs 批准内容 | 会议纪要、立项审批中的建设内容与数量 |
| E3 | 合同乙方 vs 中标单位 | 成交通知书、审批表中的单位全称 |
| E4 | 合同工期 vs 要求完成时间 | 会议纪要中的时间要求 |

依据材料未提供或未识别（在 `pending_ocr` 里）时，对应项判「无法判定」，写明缺的是哪份材料——**不要因为依据缺失就默认合同没问题**。
